# Anime OS · 精简漫剧控制台

本仓库是一套**重新收束后的骨架**：**一个 API + 一个 Web**，业务状态集中在 SQLite；OpenClaw、N8N、Dify 等作为**外挂编排**，只通过 HTTP 读写同一 API，避免多套前端、多套库各写各的。

## 设计原则

1. **单一事实源**：项目、创意、各步骤状态与产物 JSON，只存在 `anime-os-api` 的数据库里。
2. **单一用户入口**：日常操作只用本仓库的 Web（`anime-os-web`）；不再为同一业务再开第二套「主控制台」。
3. **Agent / 工作流是客户端**：OpenClaw 工具、N8N HTTP 节点，只做「调用 API」，不当数据库。
4. **可锁定步骤**：已审定的步骤写入 `locked_step_keys`，Agent 生成后续内容时应先拉 `/v1/projects/:id/context`，只读锁定产物。

## 流水线步骤 key（勿随意改名）

| key | 说明 |
|-----|------|
| `outline` | 大纲 |
| `script` | 剧本 |
| `storyboard` | 分镜脚本 |
| `char_sheet` | 角色设定 |
| `keyframes` | 关键帧 |
| `video` | 视频片段 |
| `assemble` | 成片合成 |

## API 摘要

- `GET /health` — 健康检查  
- `GET /v1/pipeline` — 步骤定义列表  
- `GET /v1/projects` — 项目列表  
- `POST /v1/projects` — 创建项目（若设置 `SERVICE_TOKEN` 则需头）  
- `GET /v1/projects/:id` — 项目详情 + 各步骤行  
- `PATCH /v1/projects/:id` — 更新标题、创意、当前步骤  
- `POST /v1/projects/:id/locks` — 更新锁定步骤  
- `PUT /v1/projects/:id/steps/:stepKey` — 写入某步 `artifact`（OpenClaw / N8N 主用）  
- `GET /v1/projects/:id/context` — Agent 拉取上下文 + 锁定产物  

写接口在设置了环境变量 `SERVICE_TOKEN` 时，要求请求头：`X-Service-Token: <同值>`。

## 与旧栈（腾讯云单机）的衔接方式

- **OpenClaw**：为每个专职 Agent 增加工具，例如 `put_step_artifact(project_id, step_key, artifact)`，内部请求本 API 的 `PUT /v1/projects/.../steps/...`；规划类 Agent 先 `GET .../context`。  
- **N8N**：用 HTTP Request 节点调用同一 API；工作流 JSON 建议 **以 n8n 内导出为准**，Git 只做备份。  
- **Dify**：若继续保留，定位为「实验应用」或「独立 RAG」，知识库与主项目库 **二选一权威**，避免双写。  
- **Mission / 其它控制台**：逐步只保留「运维/会话」，业务数据一律回指本 API。

## 本地开发

```bash
cd anime-os/api && npm install && SERVICE_TOKEN=devtoken PORT=8787 npm run dev
cd anime-os/web && npm install && ANIME_OS_SERVICE_TOKEN=devtoken VITE_API_PROXY_TARGET=http://127.0.0.1:8787 npm run dev
```

浏览器访问 Vite 地址；`/api` 由 Vite 注入 `X-Service-Token`。

## Docker 一键启动

```bash
cd anime-os
cp .env.example .env
# 编辑 .env 设置 SERVICE_TOKEN
docker compose up -d --build
```

访问 `http://<主机>:3080`（端口见 `.env` 中 `WEB_PORT`）。

## 迁移建议

不必一次性下线旧系统：可先让 **一条** N8N 流或 **一个** OpenClaw 工具指向新 API，验证「创建项目 → 写剧本步骤 → Web 可见」后再切流量。
