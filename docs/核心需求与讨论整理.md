# 足彩分析 / 模拟投注 — 核心需求与讨论整理

> 本文档汇总当前已讨论并约定的事项，作为后续开发与跨会话对齐的依据。若与代码实现不一致，以本文档为准进行修订。

---

## 1. 项目目标（概览）

- 以 **国内竞彩、北单** 为主要业务方向；数据展示与玩法逻辑对齐体彩常见形态（胜平负、让球、组合过关、胆拖等）。
- **预测思路（初版）**：针对当日开售比赛，结合 **历史欧盘、亚盘走势与最终比分/胜负**，做相对简单的胜平负或比分倾向分析；后续再扩展 **多庄家欧赔对比** 等能力。
- **技术路线补充**：接口形态上可先参考 **The Odds API** 一类（HTTP + JSON）做管道与模块划分；**竞彩/北单真实开售数据** 与境外聚合 API 数据源不同，需通过 **Provider / 适配层** 与内部统一数据模型对接（例如先用手工 JSON、页面解析等方式）。

## 2. 使用范围与数据获取（已讨论）

- **使用方式**：作者 **自用、不对公众提供产品**；实现时以本机运行、个人研究为主。
- **数据来源（竞彩示例）**：曾讨论 [500 彩票网竞彩页面](https://trade.500.com/jczq/?from=500pchome) 等页面含有赛程与奖金（赔率形态）信息；**北单** 往往在 **另一入口/栏目**，需单独梳理 URL 与字段，不与竞彩混为同一页。
- **说明**：抓取涉及反爬、页面改版、登录态等技术问题；若将程序交付或商用，仍需自行对照网站服务条款与法规。本文档仅记录需求，不构成法律建议。

## 3. 模拟投注与盈亏账本（必做）

### 3.1 功能要求

- 在系统内 **模拟下注**（非真实出票）。
- **赛果公布后**（建议统一为 **全场 90 分钟含伤停补时**，不含加时与点球大战，与竞彩常见规则一致）：  
  - 未命中：显示 **亏损**（该注本金）。  
  - 命中：显示 **盈利**（返还减本金，或等价展示）。  
- 需要 **汇总统计**：按时间段、玩法、联赛等维度查看 **总投入、总返还、净利润、命中率** 等，用于评估「整体预测/策略」的纸面收益。

### 3.2 记录字段（原则）

- **注单级**：注单号、创建时间、过关类型、是否含胆、倍数等。
- **场次级**：竞彩编号、主客队、联赛、开赛时间、玩法（含让球数）、选项（主/平/客等）。
- **快照**：下单时的 **锁定赔率**（必须保存），避免赛后页面变化导致无法复现结算。
- **结算级**：赛果、各子注是否命中、返还金额、盈亏、结算时间。

### 3.3 结算规则（模拟简化版）

- 真实体彩存在浮动 SP、限赔、官方算法差异等；**自用模拟**可采用可复现的简化规则，并在界面或文档中注明 **「模拟结算，不等同于票面实得奖金」**。
- **单关（子注）**：命中则 `返还 = 该子注本金 × 各场锁定赔率之积`（单场即 × 一项）；未中则返还为 0。
- **串关（子注）**：该子注内 **每场均猜中** 才命中；赔率按 **该子注内各场锁定赔率相乘**。
- **本金**：见下文「投注面值」。

## 4. 「几串几」组合过关（已说明的逻辑）

- **n**：所选比赛场次数。  
- **m**：系统拆出的 **子注条数**；每条子注独立判断命中与否、独立结算。
- 子注构成由玩法名称决定（如 3 串 4、4 串 11 等），可用 **配置表** 描述「每种玩法包含哪些长度的串关及条数」；实现时需与当期官方规则或自用简化表一致。
- **有胆时**：子注生成规则变化——**每一子注必须包含全部胆场**；胆场数量超过某一 `k 串 1` 的 `k` 时，该 `k` 类子注无法生成（条数为 0）。赛果后 **任一胆猜错** 时，整单按约定可 **全部判负**（与此前讨论一致）。

---

## 5. 胆拖（已约定规则）

- **胆**：必须在 **每一个子注** 中出现；所选选项参与该子注的命中判定。  
- **胆的数量**：**不设上限**（产品规则层面）。  
- **拖**：非胆场次，用于与胆组合成各子注。  
- 实现时注意与「几串几」配置联合计算 **总子注数** 与 **每条子注包含哪些场次**。

---

## 6. 组合过关种类上限

- **单次模拟母单**：最多只能选择 **5 种** 不同的 **组合过关类型**（例如同时勾选的过关方式种类 ≤ 5）。  
- 第 6 种应在交互或校验中禁止。  
- 若多种类型同时生效：**总子注数** 一般为各类型生成子注之和（若与真实体彩「多选互斥」规则不一致，应在实现或文档中单独说明）。

---

## 7. 投注面值

- **1 注 = 2 元人民币**（模拟）。  
- **总本金** = **子注总条数 × 2 元** ×（若以后支持 **倍数**，再 × 倍数）。  
- 每条子注对应一条账本记录，便于赛后逐注展示盈亏。

---

## 8. 与预测模块的关系

- **预测**：输出概率、建议或自动生成选项（可选）。  
- **模拟账本**：记录实际（模拟）发生的选项、金额与结算。  
- 建议支持 **来源标记**（人工模拟 / 模型建议），便于对比不同策略的总体盈亏。

---

## 9. Web 与真实数据（已实现）

- **Flask 页面**：`python3 -m web.app`，默认 `http://127.0.0.1:5000`。  
- **数据源**：  
  - **`source=jc500`**（默认）：抓取 500 彩票网竞彩列表页当日 **真实 SP**（胜平负、让球胜平负）；可选 `date=YYYY-MM-DD`。  
  - **`source=odds_api`**：The Odds API v4 **h2h 十进制** 多庄数据；需 **`ODDS_API_KEY`**。  
  - **`source=file`**：本地 JSON（`FOOTBALL_ODDS_DATA`）。  
- 境外 API 与体彩开售赔率 **来源不同**，勿混为一谈。

## 10. 后续开发时可拆阶段（建议）

1. 数据：竞彩（及北单）赛程与赔率快照、赛果入库；内部统一比赛与盘口模型。  
2. 预测：先做 **胜平负（或让球胜平负）**；比分用更简单的方式（如 Top-N 或基于 1X2 的简化）后置。  
3. 模拟：单关 → 标准 n 串 m → **胆拖** → **多类型组合（≤5 种）** 与汇总报表。
